# Step A protocol: contemporary P3 supplement (fixed before collection)

Status: revised after the 2026-09-17 review (scenario-level inference, pinned provider, batch-separated analysis). Nothing below has been run.

## Purpose
Add four contemporary scenarios for each of the two under-sampled gap types (missing reason, implied not stated; the
historical batch has two of each, which stay in the historical batch) and collect eight contemporary missing-evidence
comparison cases (the same documents as P3_021-P3_028) in the same batch, so that a within-batch comparison across gap
types shares collection date, endpoints, settings, and judge. Batch confounding is reduced, not eliminated.

## Scenario set (frozen)
- New: P3_029-P3_032 (missing reason), P3_033-P3_036 (implied not stated); file `p3_supplementary_r2/p3_source_data.json`
  (generator `generate_supplementary_p3_round2.py`, sha256 to be recorded at launch).
- Contemporary comparison cases: P3_021-P3_028 (missing evidence; identical documents to the historical
  supplementary batch of Feb 2026), re-collected in the same batch. Output directory `results_supplementary_r2/`
  for the new scenarios and `results_supplementary_r2_controls/` for the re-collected controls.

## Endpoints and settings (record at launch: date, model id, host, reasoning setting, max tokens, temperature)
- gpt-4o-2024-11-20 (OpenAI), claude-sonnet-4-5-20250929 (Anthropic), gemini-2.5-pro (Google), MiniMax-M2.5
  (MiniMax legacy endpoint), DeepSeek-V3.2 open weights via OpenRouter (provider recorded per call; DeepInfra preferred),
  reasoning enabled. Temperature 0.0; max output tokens as in the core run (2,048; 16,384 for DeepSeek; 8,192 Gemini).
- DeepSeek: the OpenRouter provider is PINNED (no fallback); the serving provider, model id and settings are persisted
  in every turn record. The contemporary DeepSeek observations form their own serving condition (key `deepseek-v3.2`)
  and are never pooled with the February observations (key `deepseek-r1`).
- Collection order: for each model, interleave new scenarios and control scenarios (alternate) within one session.
- Stop rule: collect exactly the 16 x 5 conversations; document any failure; do not switch endpoints or extend collection.

## Judge
- Primary: claude-opus-4-6 with the unchanged P3 rubric (`run_p3_judge.py`); judge prompts generated by
  `score_responses.py` from the frozen scenario files. Cross-judge: gpt-5.2 if still available via API, otherwise omitted
  and stated. Author audit of every fabrication flag in the batch (human judgment, recorded in the checklist).

## Analysis plan (frozen; implemented in scripts/gap_types_batched.py)
1. Primary endpoint: scenario-level "any fabrication among the five-model panel" (one observation per scenario).
   Pair-level counts (model x scenario) are reported as descriptive breakdowns only; no pair-level tests.
2. Two prespecified contrasts in the contemporary batch, Fisher exact two-sided at scenario level, Holm-adjusted:
   C1 missing-evidence controls (8) vs missing reason (4); C2 controls (8) vs implied not stated (4).
   With 4 scenarios per new type the tests have little power; they are reported as bounded evidence, not confirmation.
3. Historical batch (Feb 2026) reported separately, as in the submitted paper, with the corrected caveats.
4. Control drift check: P3_021-P3_028 contemporary vs. historical per model (same documents), reported as agreement
   rates; DeepSeek reported as host change, not drift.
5. No pooling across batches. Scenario/code hashes and run settings recorded at launch in `stepA_launch_record.json`.

## Cost estimate
16 scenarios x 5 models x 12 turns: ~ $10 API; judging 80 entries with Opus 4.6: ~ $4; cross-judge if available ~ $4.
